Tolong lakukan audit menyeluruh terhadap implementasi Phase 5 Step 4 (Auto-Knowledge Loop) pada repo AINA.

Tujuan audit:
- Memastikan draft KB bisa dibuat, disimpan, dan dikelola
- Memastikan autoGenerateDrafts() berjalan dengan benar
- Memastikan semua perubahan additive-only dan tidak mengganggu /api/chat
- Memastikan tidak ada infinite loop / spam draft

==================================================

1. Validasi Struktur Perubahan

- File baru apa saja yang ditambahkan?
- Apakah ada:
  - draftStorageService.js
  - perubahan di knowledgeGapService.js
  - update di knowledgeInsights.js
- File apa saja yang diubah?
- Apakah perubahan additive-only?
- Apakah server.js hanya ditambah route saja (tidak ubah logic lain)?

==================================================

2. Validasi Database (kb_drafts)

- Apakah tabel kb_drafts digunakan dalam code?
- Apakah field berikut digunakan dengan benar:
  - id
  - topic
  - title
  - content
  - tags
  - status
  - created_at

- Apakah insert ke kb_drafts dilakukan melalui service (bukan langsung raw query di route)?

- Apakah default status = "draft"?

==================================================

3. Validasi Draft Storage Service

File: server/services/draftStorageService.js

Cek fungsi:

1. saveDraft(draft)
- Apakah menerima:
  - topic
  - title
  - content
  - suggested_tags
- Apakah benar-benar insert ke Supabase?
- Apakah return object hasil insert?

2. getDrafts(status)
- Bisa filter berdasarkan status?
- Default = draft?

3. updateDraftStatus(id, status)
- Apakah bisa update ke:
  - approved
  - rejected

- Apakah ada validasi status?

==================================================

4. Validasi Auto Pipeline

Function: autoGenerateDrafts()

Cek:

- Apakah memanggil getRecommendedTopics()?
- Apakah hanya ambil topic dengan:
  - priority = high

- Apakah ada limit:
  - maksimal 3 topic per run?

- Apakah flow-nya benar:
  topic → generateDraft → saveDraft

- Apakah return:
  {
    generated: number,
    topics: [...]
  }

==================================================

5. Validasi API Routes

Cek endpoint baru:

1. POST /api/internal/knowledge/auto-draft
- Menjalankan autoGenerateDrafts()

2. GET /api/internal/knowledge/drafts
- Mengambil list draft

3. PATCH /api/internal/knowledge/drafts/:id
- Update status draft

Cek:
- route sudah di-mount?
- response JSON konsisten?

==================================================

6. Validasi Security

- Apakah semua endpoint pakai:
  x-internal-key === process.env.INTERNAL_API_KEY

- Tanpa key → 401 / 403?
- Dengan key salah → 403?
- Endpoint tidak bisa diakses publik?

==================================================

7. Validasi Non-Breaking

Jawab tegas:

- Apakah /api/chat tetap tidak berubah?
- Apakah retrieval knowledge_base tetap sama?
- Apakah kb_drafts tidak ikut ke retrieval?
- Apakah error di auto-draft tidak mempengaruhi chat?

==================================================

8. Validasi Anti-Spam & Safety

Cek:

- Apakah ada limit jumlah draft per run? (max 3)
- Apakah tidak ada loop otomatis tanpa trigger?
- Apakah auto-draft hanya jalan saat endpoint dipanggil (bukan tiap chat)?

==================================================

9. Simulasi Flow Nyata

Jelaskan:

- Admin hit /auto-draft
- Sistem ambil top topic
- Generate draft
- Simpan ke kb_drafts
- Admin bisa lihat di /drafts
- Admin approve/reject

==================================================

10. Risiko & Bug Potensial

Cari kemungkinan:

- draft duplicate (topic sama berkali-kali)
- generateDraft gagal tapi tetap disimpan
- draft kosong / content null
- JSON parsing error
- Supabase insert gagal
- endpoint bisa disalahgunakan (spam request)
- race condition kalau dipanggil bersamaan

==================================================

11. Kesimpulan

Berikan verdict:
- AMAN
- PERLU FIX
- BERISIKO

Jelaskan alasan secara tegas.

==================================================

12. Bonus Improvement

Berikan saran ringan:

- dedup draft berdasarkan topic
- limit per hari (misalnya max 10 draft/day)
- save draft ke kategori tertentu
- preview draft sebelum save
- auto-tagging lebih pintar
- optional auto-publish (dengan flag, default OFF)

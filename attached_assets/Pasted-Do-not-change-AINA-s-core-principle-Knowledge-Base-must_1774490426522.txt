Critical rules:
1. Knowledge Base stays first.
   - If KB is relevant and strong enough, it must remain the main grounding source.
   - Do not bypass KB just because a model is available.
   - Pinned / verified internal updates must still remain above external sources and above model memory.

2. Models are not sources.
   - Models should compose and explain answers.
   - KB, pinned updates, and external retrieval remain the actual source layers.

3. Add model routing before generation, not before retrieval.
   - Retrieval logic should stay intact.
   - Model routing should happen after source/context preparation.

A. Lightweight queries → cheap model

- short factual questions
- simple definitions
- FAQ-like questions
- suggested question generation
- low-risk, low-complexity responses
- cases where KB is already strong and answer generation is simple

B. Standard queries → main model
Use the main model for:
- normal user chat
- procedural answers
- recommendation answers
- memory-aware responses
- moderate reasoning
- cases where response quality matters more

C. Heavy/admin-only queries → premium model (optional, restricted)
Use premium models only for:
- admin/internal testing
- debugging
- complex internal tasks
- long-form or difficult reasoning
Do not use premium models for normal user traffic by default.
